# Google Calendar Supabase Schema Reference

## Quick Overview

**Purpose**: Cache Google Calendar events locally for fast UI performance  
**Sync Method**: Webhook-based incremental sync using Google Calendar push notifications  
**Single User**: One Google account, primary calendar only  

---

## Table Schemas

### 1. `google_oauth_tokens` (OAuth Credentials)

```sql
CREATE TABLE public.google_oauth_tokens (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_label TEXT NOT NULL DEFAULT 'default',
  refresh_token TEXT NOT NULL,              -- Long-lived token for API access
  access_token TEXT,                        -- Short-lived token (1 hour)
  token_expiry TIMESTAMPTZ,                 -- When access_token expires
  scopes TEXT NOT NULL DEFAULT 'https://www.googleapis.com/auth/calendar',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_label)
);

CREATE INDEX idx_oauth_tokens_user_label ON public.google_oauth_tokens(user_label);
```

**Single Row**: Only one user ('default')  
**Security**: Service role only (RLS enabled)  
**Token Refresh**: Edge functions auto-refresh access_token using refresh_token  

---

### 2. `gcal_sync_state` (Sync Token Tracking)

```sql
CREATE TABLE public.gcal_sync_state (
  calendar_id TEXT PRIMARY KEY DEFAULT 'primary',
  next_sync_token TEXT,                     -- Google's incremental sync token
  last_full_sync_at TIMESTAMPTZ,            -- Last complete sync
  last_incremental_sync_at TIMESTAMPTZ,     -- Last incremental sync
  status TEXT DEFAULT 'idle',               -- 'idle' | 'syncing' | 'error'
  error_message TEXT,                       -- Last error details
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

**Single Row**: Only 'primary' calendar  
**Key Field**: `next_sync_token` - used by Google Calendar API for incremental sync  
**Sync Logic**: 
- Full sync: Fetches all events, stores new `next_sync_token`
- Incremental sync: Uses `next_sync_token` to fetch only changes

---

### 3. `gcal_watch_channels` (Webhook Management)

```sql
CREATE TABLE public.gcal_watch_channels (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  calendar_id TEXT NOT NULL DEFAULT 'primary',
  channel_id TEXT NOT NULL,                 -- UUID generated by us
  resource_id TEXT NOT NULL,                -- UUID returned by Google
  channel_token TEXT NOT NULL,              -- Secret token for validation
  expiration_ms BIGINT NOT NULL,            -- Unix timestamp (ms)
  expiration_at TIMESTAMPTZ NOT NULL,       -- Human-readable expiration
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(calendar_id)
);

CREATE INDEX idx_watch_channels_expiration ON public.gcal_watch_channels(expiration_at);
```

**Single Row**: Only 'primary' calendar  
**Webhook Flow**:
1. Edge function calls `calendar.events.watch()` → Google returns `channel_id` + `resource_id`
2. Google sends POST to webhook when events change
3. Webhook validates `X-Goog-Channel-Token` header matches `channel_token`
4. Webhook triggers incremental sync

**Expiration**: Channels expire after ~7 days, must be renewed

### 4. `gcal_events_cache` (Event Cache)

```sql
CREATE TABLE public.gcal_events_cache (
  calendar_id TEXT NOT NULL DEFAULT 'primary',
  event_id TEXT NOT NULL,
  
  -- Core metadata
  status TEXT,                              -- 'confirmed' | 'tentative' | 'cancelled'
  html_link TEXT,                           -- Link to event in Google Calendar
  created TIMESTAMPTZ,                      -- Event creation time
  updated TIMESTAMPTZ,                      -- Last modification time
  
  -- Event details
  summary TEXT,                             -- Event title
  description TEXT,                         -- Event description
  location TEXT,                            -- Event location
  color_id TEXT,                            -- Google Calendar color ID (1-11)
  
  -- Date/time (JSONB for flexibility)
  start_json JSONB NOT NULL,                -- {date: "2026-02-05"} OR {dateTime: "...", timeZone: "..."}
  end_json JSONB NOT NULL,                  -- Same format as start_json
  
  -- Recurrence
  recurrence JSONB,                         -- Array of RRULE strings
  recurring_event_id TEXT,                  -- Parent recurring event ID
  original_start_time JSONB,                -- For recurring event instances
  
  -- People
  organizer_json JSONB,                     -- {email, displayName, self}
  creator_json JSONB,                       -- {email, displayName, self}
  attendees_json JSONB,                     -- Array of {email, displayName, responseStatus}
  
  -- Reminders & settings
  reminders_json JSONB,                     -- {useDefault, overrides: [{method, minutes}]}
  visibility TEXT,                          -- 'default' | 'public' | 'private'
  transparency TEXT,                        -- 'opaque' | 'transparent'
  
  -- Advanced fields
  ical_uid TEXT,                            -- iCalendar UID
  sequence INT DEFAULT 0,                   -- Event version number
  event_type TEXT,                          -- 'default' | 'outOfOffice' | 'focusTime'
  hangout_link TEXT,                        -- Google Meet link
  conference_data_json JSONB,               -- Full conference details
  attachments_json JSONB,                   -- File attachments
  extended_properties_json JSONB,           -- Custom properties
  
  -- Full backup
  raw_event_json JSONB NOT NULL,            -- Complete Google Calendar event JSON
  
  -- Cache metadata
  deleted BOOLEAN DEFAULT FALSE,            -- Soft delete flag
  last_synced_at TIMESTAMPTZ DEFAULT NOW(), -- Last sync timestamp
  
  PRIMARY KEY (calendar_id, event_id)
);

-- Indexes for fast queries
CREATE INDEX idx_events_start ON public.gcal_events_cache USING GIN (start_json);
CREATE INDEX idx_events_status ON public.gcal_events_cache(status) WHERE deleted = FALSE;
CREATE INDEX idx_events_recurring ON public.gcal_events_cache(recurring_event_id) WHERE recurring_event_id IS NOT NULL;
CREATE INDEX idx_events_updated ON public.gcal_events_cache(updated);
CREATE INDEX idx_events_deleted ON public.gcal_events_cache(deleted);
```

**Why JSONB for dates?**  
Google Calendar events have two date formats:
- **All-day events**: `{date: "2026-02-05"}`
- **Timed events**: `{dateTime: "2026-02-05T14:30:00Z", timeZone: "America/New_York"}`

JSONB allows flexible storage of both.

**Soft Deletes**: Events are marked `deleted=true` instead of hard deleted (preserves history)

## Row-Level Security (RLS) Policies

```sql
-- Events cache: Public can read, service role can write
ALTER TABLE public.gcal_events_cache ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Anyone can read cached events"
  ON public.gcal_events_cache FOR SELECT
  USING (deleted = false);

CREATE POLICY "Service role manages events"
  ON public.gcal_events_cache FOR ALL
  USING (auth.role() = 'service_role');

-- OAuth tokens: Service role only
ALTER TABLE public.google_oauth_tokens ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Service role manages oauth tokens"
  ON public.google_oauth_tokens FOR ALL
  USING (auth.role() = 'service_role');

-- Sync state: Service role only
ALTER TABLE public.gcal_sync_state ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Service role manages sync state"
  ON public.gcal_sync_state FOR ALL
  USING (auth.role() = 'service_role');

-- Watch channels: Service role only
ALTER TABLE public.gcal_watch_channels ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Service role manages watch channels"
  ON public.gcal_watch_channels FOR ALL
  USING (auth.role() = 'service_role');
```

**Security Model**:
- Frontend can **read** cached events (via `gcal-events` edge function)
- Frontend **cannot** write to cache directly
- All writes go through edge functions with service role access

## Query Examples

### Fetch Events for a Date Range
```sql
SELECT 
  event_id,
  summary,
  start_json,
  end_json,
  location,
  color_id
FROM gcal_events_cache
WHERE 
  calendar_id = 'primary'
  AND deleted = false
  AND (
    (start_json->>'date')::date BETWEEN '2026-02-01' AND '2026-02-28'
    OR
    (start_json->>'dateTime')::timestamptz BETWEEN '2026-02-01' AND '2026-02-28'
  )
ORDER BY 
  COALESCE(
    (start_json->>'date')::date::text,
    (start_json->>'dateTime')::timestamptz::text
  );
```

### Find All-Day Events
```sql
SELECT event_id, summary, start_json->>'date' as event_date
FROM gcal_events_cache
WHERE 
  calendar_id = 'primary'
  AND deleted = false
  AND start_json ? 'date'  -- Has 'date' key (all-day event)
ORDER BY start_json->>'date';
```

### Find Recurring Events
```sql
SELECT event_id, summary, recurrence
FROM gcal_events_cache
WHERE 
  calendar_id = 'primary'
  AND deleted = false
  AND recurrence IS NOT NULL;
```

### Check Sync Status
```sql
SELECT 
  calendar_id,
  status,
  last_full_sync_at,
  last_incremental_sync_at,
  error_message,
  next_sync_token IS NOT NULL as has_sync_token
FROM gcal_sync_state
WHERE calendar_id = 'primary';
```

### Check Webhook Channel Status
```sql
SELECT 
  channel_id,
  resource_id,
  expiration_at,
  CASE
    WHEN expiration_at < NOW() THEN 'expired'
    WHEN expiration_at < NOW() + INTERVAL '1 day' THEN 'expiring_soon'
    ELSE 'active'
  END as status
FROM gcal_watch_channels
WHERE calendar_id = 'primary';
```

## Maintenance Queries

### Soft Delete Old Events (Cleanup)
```sql
-- Mark events older than 1 year as deleted
UPDATE gcal_events_cache
SET deleted = true
WHERE 
  calendar_id = 'primary'
  AND deleted = false
  AND (
    (start_json->>'date')::date < NOW() - INTERVAL '1 year'
    OR
    (start_json->>'dateTime')::timestamptz < NOW() - INTERVAL '1 year'
  );
```

### Hard Delete Old Soft-Deleted Events
```sql
-- Permanently remove events deleted over 90 days ago
DELETE FROM gcal_events_cache
WHERE 
  calendar_id = 'primary'
  AND deleted = true
  AND last_synced_at < NOW() - INTERVAL '90 days';
```

### Reset Sync State (Force Full Sync)
```sql
-- Clear sync token to force next sync to be full
UPDATE gcal_sync_state
SET 
  next_sync_token = NULL,
  status = 'idle',
  error_message = NULL
WHERE calendar_id = 'primary';
```

## Performance Notes

### Indexes Explained

1. **`idx_events_start` (GIN on start_json)**  
   - Fast queries on date ranges
   - Supports both `date` and `dateTime` queries

2. **`idx_events_status` (WHERE deleted = FALSE)**  
   - Partial index for active events only
   - Reduces index size

3. **`idx_events_recurring`**  
   - Fast lookup of recurring event instances
   - Only indexes events with `recurring_event_id`

4. **`idx_events_updated`**  
   - Fast sorting by modification time
   - Useful for "recently changed" queries

5. **`idx_events_deleted`**  
   - Fast filtering of deleted events
   - Supports cleanup queries

### Estimated Storage

- **Per event**: ~2-5 KB (depends on description, attendees, etc.)
- **1000 events**: ~2-5 MB
- **10,000 events**: ~20-50 MB

**Recommendation**: Periodically clean up old events (>1 year) to keep cache size manageable.

## Summary

This schema provides:
- ✅ **Fast reads**: All events cached locally, no API calls needed
- ✅ **Auto-sync**: Webhook-based incremental updates
- ✅ **100% fidelity**: All Google Calendar fields preserved
- ✅ **Flexible dates**: JSONB handles all-day and timed events
- ✅ **Secure**: RLS prevents direct client writes
- ✅ **Scalable**: Incremental sync, not full refresh
- ✅ **Maintainable**: Soft deletes, cleanup queries

**No custom fields added** - all data comes directly from Google Calendar API.
